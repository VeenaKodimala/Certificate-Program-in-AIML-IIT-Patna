Topic 01 · Foundations
AI & Computer Foundations

Gen AI, AI vs ML vs DL, and the basic computer concepts every Python course starts with.

Topic 01 · Foundations
What is it? Why is it used?
What is it?

This topic covers the big-picture ideas you need before writing any code: what Generative AI is, how AI/ML/DL relate to each other, and how a computer actually runs the programs you write — hardware, software, the kernel, IDEs, terminals, and file types.

Why is it used?

Exams love to test whether you can tell these layered concepts apart (AI vs ML vs DL, hardware vs software, IDE vs terminal). Understanding "how code runs" also helps you debug errors later — you'll know whether a problem is in your code, your environment, or your machine.

Topic 01 · Foundations
Simple explanation

Gen AI (Generative AI) is AI that creates new content — text, images, code, audio — instead of just predicting a number or a label. ChatGPT writing an essay or Copilot writing code are both Gen AI.

AI → ML → DL (nested, not equal)

  • AI = the broad goal: machines that act intelligently.
  • ML = a subset of AI where machines learn patterns from data instead of being hard-coded.
  • DL = a subset of ML that uses multi-layer neural networks.

Is AI good or bad?

  • Neither — it's a tool. Impact depends on how it is built, trained, and used.
  • Good: medical diagnosis help, accessibility tools, automation of boring tasks.
  • Risky: bias in training data, misinformation, job displacement if unmanaged.

Computer basics: A computer takes input, processes it using logic on data, and produces output. Everything you code eventually maps to this input → process → output cycle.

Hardware vs Software vs Kernel

Hardware

  • Physical parts you can touch: CPU, RAM, hard disk, keyboard, monitor.
  • Does the actual work of executing instructions.

Software

  • Instructions/programs that tell hardware what to do.
  • Two kinds: System software (OS, drivers) and Application software (Chrome, VS Code, Python).

The Kernel is the core part of the Operating System. It sits between hardware and software, managing memory, CPU time, and devices so that every app doesn't need to talk to hardware directly.

IDE vs Terminal vs File Types

IDE (e.g. VS Code)

  • A text editor + tools (debugger, extensions, run button) combined.
  • Makes writing and running code easier with visual help.

Terminal / Command Line

  • A text-only way to talk directly to the OS using typed commands.
  • Used to run scripts, install packages, navigate folders (cd, ls/dir).

Common file types you'll meet: .py (Python script), .ipynb (Jupyter/Colab notebook), .csv (tabular data), .json (structured data), .txt (plain text), .exe (Windows executable / software).

How code runs (Python, step by step): 1) You write code in an editor/IDE → 2) You run it via terminal or IDE's run button → 3) The Python interpreter reads your code line by line → 4) It translates it to something the machine understands and executes it → 5) Output is shown to you.

Topic 02 · Getting Started
What is it? Why is it used?
What is it?

The environment and first building blocks of Python: where you write code (VS Code, Google Colab), how you connect to external services (APIs and API keys), how you track code changes (Git), and the core syntax — variables, packages, arithmetic, print(), input(), and f-strings.

Why is it used?

Before learning logic, you need a place to write and run code, and a way to store and display values. These fundamentals appear in almost every single exam question, directly or indirectly.

VS Code

Google Colab

Topic 03 · Control Flow
Conditions & Loops

Making decisions with if/elif/else and repeating work with for and while — the two engines of program logic.

Topic 03 · Control Flow
What is it? Why is it used?
What is it?

Conditions (if/elif/else) let a program choose between different actions. Loops (for, while) let a program repeat an action multiple times without rewriting the same code again and again.

Why is it used?

Almost every real program needs to react differently to different data, and process many items (a list of students, rows of a file). Conditions and loops are how Python does both.

Topic 03 · Control Flow
Simple explanation

How conditions are evaluated: Python checks the if condition first. If it's True, that block runs and Python skips every elif/else below. If False, it checks the next elif, and so on. else runs only if nothing above was True.

marks = 72 if marks >= 90: print("Grade A") elif marks >= 60: print("Grade B") else: print("Grade C")
Grade B

Why indentation matters: Python uses indentation (spaces) instead of curly braces {} to show which lines belong inside a block (if/for/while/function). Wrong or inconsistent indentation causes an IndentationError or changes program logic silently.

Correct indentation

  • if x > 0:
        print("positive")
  • 4 spaces is the standard convention.

Broken indentation

  • if x > 0:
    print("positive")
  • Missing indent → IndentationError: expected an indented block.

for vs while: Use for when you know what you're looping over (a list, a range, a string). Use while when you loop based on a condition staying true, and you don't know exactly how many times in advance.

for loop

  • Loops over a known sequence: for i in range(5):
  • Stops automatically when the sequence ends.

while loop

  • Loops while a condition is True: while count < 5:
  • Risk: forgetting to update the condition variable → infinite loop.

break vs continue: break exits the loop completely, immediately. continue skips only the current iteration and moves to the next one — the loop keeps running.

Topic 03 · Control Flow
Easy example
for i in range(1, 6): if i == 3: continue if i == 5: break print(i)
1 2 4

Walkthrough: i=1 → prints. i=2 → prints. i=3 → continue skips printing, jumps to i=4. i=4 → prints. i=5 → break stops the loop entirely (5 is never printed).

Topic 03 · Control Flow
Important points & exam traps
Important points
  • elif/else are optional; you can have plain if alone, or many elifs.
  • Only one branch of an if/elif/else chain ever runs, even if multiple conditions would technically be True.
  • range(5) generates 0,1,2,3,4 — 5 numbers, stopping before 5.
  • A while True: loop needs an internal break or it will never stop.
  • Both loop types support break and continue.
Common mistakes / exam traps
  • Mixing tabs and spaces for indentation in the same file — Python may raise a TabError.
  • Forgetting the colon : at the end of if/for/while lines → SyntaxError.
  • Using = (assignment) instead of == (comparison) inside a condition.
  • Writing a while loop and forgetting to update the loop variable, causing an infinite loop.
  • Thinking continue stops the loop — it only skips to the next round.

QUICK REVISION

  • Indentation defines blocks in Python — no braces.
  • for = known number of iterations/sequence; while = condition-based, unknown count.
  • break = exit loop now. continue = skip this round only.
  • range(n) goes from 0 to n-1.

Topic 04 · Reusable Code
Functions

Packaging code into reusable blocks with def, return values properly, and understand variable scope.

Topic 04 · Reusable Code
What is it? Why is it used?
What is it?

A function is a named, reusable block of code that performs a specific task. You define it once with def and can call it as many times as needed with different inputs (arguments).

Why is it used?

Functions avoid repeating the same code everywhere, make programs easier to read/test/debug, and let you break a big problem into small, manageable pieces.

Topic 04 · Reusable Code
Simple explanation

Defining and calling: Use def function_name(parameters): to define, then call it later using function_name(arguments).

def greet(name): return f"Hello, {name}!" message = greet("Divya") print(message)
Hello, Divya!

return vs print: print() only displays a value on screen — it doesn't give the value back to your code. return sends a value back to wherever the function was called, so it can be stored in a variable and reused.

def add_print(a, b): print(a + b) def add_return(a, b): return a + b x = add_print(2, 3) # prints 5, but x is None y = add_return(2, 3) # nothing printed, y = 5 print(x, y)
5 None 5

Local vs Global variables: A local variable is created inside a function and only exists while that function runs — it's invisible outside. A global variable is defined outside all functions and can be read from anywhere (but not changed inside a function unless you use the global keyword).

total = 100 # global def use_local(): total = 5 # this is a NEW local variable, separate from the global one print("inside:", total) use_local() print("outside:", total)
inside: 5 outside: 100

Lists with functions: You can pass a list into a function, and modify it in place using list methods like append() — because lists are mutable, the change is visible outside the function too.

Topic 04 · Reusable Code
Easy example
def add_marks(marks_list, new_mark): marks_list.append(new_mark) return marks_list scores = [80, 90] add_marks(scores, 75) print(scores)
[80, 90, 75]
Topic 04 · Reusable Code
Important points & exam traps
Important points
  • A function without an explicit return statement returns None by default.
  • Parameters are the placeholder names in the definition; arguments are the actual values passed when calling.
  • You can return multiple values from one function: return a, b (packed as a tuple).
  • Modifying a mutable argument (like a list) inside a function changes the original object outside too.
  • Functions can have default parameter values: def greet(name="Guest"):.
Common mistakes / exam traps
  • Using print() inside a function and then trying to use its 'return value' elsewhere — it's actually None.
  • Forgetting parentheses when calling a function: greet refers to the function object, not its result — you need greet().
  • Trying to modify a global variable inside a function without the global keyword — Python creates a new local variable instead, and the original is unchanged.
  • Assuming a local variable is accessible outside its function — it raises a NameError.

Quick revision summary
QUICK REVISION

  • No return statement → function result is None.
  • Local variables live only inside their function; global variables live outside, everywhere.
  • Changing global variables inside a function needs the global keyword.
  • Lists passed into functions can be modified in place because they're mutable.

Topic 05 · Storing Data
Data Structures — List, Dict, Tuple, Set

Python's four core containers, how they differ, and set operations like union/subset/superset.

Topic 05 · Storing Data
What is it? Why is it used?
What is it?

Data structures are ways to store collections of values. Python's four built-in core containers are List, Tuple, Set, and Dictionary — each with different rules about order, duplicates, and whether they can change after creation.

Why is it used?

Choosing the right structure matters for both correctness and speed — e.g. you use a set to remove duplicates instantly, a dictionary to look things up by name instead of position, and a tuple to protect data that should never change (like coordinates).

Topic 05 · Storing Data
Simple explanation

Lists — ordered, changeable (mutable), allow duplicates. Written with square brackets [].

nums = [4, 1, 3] nums.append(9) print(nums) nums.pop() print(nums) nums.sort() print(nums) nums.reverse() print(nums)
[4, 1, 3, 9] [4, 1, 3] [1, 3, 4] [4, 3, 1]

append(x) adds one item to the end. pop() removes and returns the last item (or a specific index if given, e.g. pop(0)). sort() arranges ascending in place; reverse() flips the current order.

for item in ["a","b","c"]: print(item.upper())
A B C

Dictionaries — unordered (insertion order preserved since Python 3.7 but not index-based), store key:value pairs, keys must be unique.

student = {"name": "Divya", "marks": 91} print(student["name"]) student["marks"] = 95 print(student)
Divya {'name': 'Divya', 'marks': 95}
List vs Dictionary

List

  • Access by position/index: list[0]
  • Good for ordered sequences of similar items.

Dictionary

  • Access by key name: dict['key']
  • Good for labelled data (like a record with named fields).

Tuples — ordered, but immutable (cannot be changed after creation). Written with parentheses (). Used for fixed data like coordinates (x, y).

Sets — unordered, no duplicates allowed, written with curly braces {} (empty set must use set(), since {} means an empty dict).

a = {1, 2, 3} b = {2, 3, 4} print(a.union(b)) print(a.issubset({1,2,3,4,5})) print({1,2,3,4,5}.issuperset(a))
{1, 2, 3, 4} True True

Union combines all unique elements from both sets. A is a subset of B if every element of A is also in B. B is a superset of A under the same condition — subset and superset are just two directions of the same relationship.

Files: use open("data.txt", "r") to read, "w" to write (overwrites), "a" to append. Best practice: use with open(...) as f: so the file auto-closes.

with open("notes.txt", "w") as f: f.write("Hello file!") with open("notes.txt", "r") as f: print(f.read())

Topic 05 · Storing Data
Important points & exam traps
Important points
  • Mutable = can change after creation: List, Dict, Set. Immutable = cannot: Tuple, String, Int.
  • Ordered (keeps insertion order, index-based): List, Tuple. Unordered/no reliable index: Set.
  • Duplicates allowed: List, Tuple. Duplicates NOT allowed: Set, and Dictionary keys (values can repeat).
  • Indexing (obj[0]) works on List, Tuple, String — NOT on Set (unordered) or Dict (use key instead).
  • Dictionaries use key:value pairs; keys must be unique and are typically strings or numbers.
Common mistakes / exam traps
  • Writing {} expecting an empty set — it actually creates an empty dictionary. Use set().
  • Trying to change a tuple's item: t[0] = 5 → TypeError (tuples are immutable).
  • Assuming a set keeps the order you inserted items in — it does not guarantee order.
  • Confusing append() (adds 1 item) with extend() (adds multiple items from another list).
  • Forgetting that pop() without an index removes the last item, not the first.

Topic 06 · Numerical Python
NumPy — Arrays & Matrix Operations

Fast numeric arrays, reshaping, matrix multiplication vs element-wise, broadcasting, and scaling techniques.

Topic 06 · Numerical Python
What is it? Why is it used?
What is it?

NumPy (Numerical Python) provides the array — a fast, memory-efficient way to store and operate on numbers, especially in grids (matrices). It underlies almost every data science and ML library.

Why is it used?

Python lists are slow for heavy number-crunching and don't support element-wise math directly. NumPy arrays are faster, support vectorised operations (no manual loops needed), and are the standard input format for ML models.

Topic 06 · Numerical Python
Simple explanation

Creating arrays & shape: np.array([1,2,3]) creates a 1-D array. .shape tells you the dimensions — very commonly tested.

import numpy as np a = np.array([[1,2,3],[4,5,6]]) print(a.shape) print(a.ndim)
(2, 3) 2

Shape (2, 3) means 2 rows, 3 columns. ndim = number of dimensions (here, 2 = a matrix).

reshape() — changing the shape without changing the data
b = np.array([1,2,3,4,5,6]) print(b.reshape(2,3))
[[1 2 3] [4 5 6]]

reshape(rows, cols) only works if rows × cols = total elements. 6 elements → (2,3) or (3,2) or (6,1) all work; (2,4) would fail with a ValueError because 2×4=8 ≠ 6.

Element-wise operations vs Matrix multiplication vs dot()

Element-wise (*) multiplies matching positions directly — arrays must be the same shape (or broadcastable). Matrix multiplication (@ or np.dot/np.matmul) follows linear algebra rules — rows of the first × columns of the second.

x = np.array([[1,2],[3,4]]) y = np.array([[5,6],[7,8]]) print(x * y) # element-wise print(x.dot(y)) # matrix / dot product
[[ 5 12] [21 32]] [[19 22] [43 50]]

For x.dot(y): top-left result = (1×5 + 2×7) = 19. Each output cell = sum of (row of x) × (column of y), element by element.

hstack() and vstack()
p = np.array([1,2]) q = np.array([3,4]) print(np.hstack((p,q))) print(np.vstack((p,q)))
[1 2 3 4] [[1 2] [3 4]]

hstack joins arrays side-by-side (horizontally). vstack stacks them on top of each other (vertically), creating a new row for each array.

Broadcasting

Broadcasting lets NumPy perform operations between arrays of different shapes by automatically 'stretching' the smaller one — without actually copying data.

m = np.array([[1,2,3],[4,5,6]]) print(m + 10)
[[11 12 13] [14 15 16]]

Here the scalar 10 is broadcast across every element. Broadcasting also works between a (2,3) array and a (1,3) or (3,) array — the smaller shape is repeated to match.

np.random.randn() vs np.random.randint()

np.random.randn(n)

  • Draws from a Normal (Gaussian) distribution — mean 0, std dev 1.
  • Returns floats, can be negative or positive, mostly clustered near 0.

np.random.randint(low, high)

  • Draws random integers uniformly between low (inclusive) and high (exclusive).
  • No 'bell curve' — every integer in range is equally likely.

Normal distribution is the classic bell-shaped curve — most values cluster around the mean, fewer values appear far away (both directions).

Standardization vs Min-Max Scaling

Standardization (Z-score)

  • Formula: (x - mean) / std
  • Result has mean 0, std 1. Keeps outlier influence, handles varying scales well.

  • Formula: (x - min) / (max - min)
  • Squeezes data into a fixed [0,1] range. Sensitive to outliers (they stretch the range).

Topic 09 · Structured Storage
What is it? Why is it used?
What is it?

A database is an organised system for storing, retrieving, and managing data. SQLite is a lightweight, file-based relational database engine built into Python (via the sqlite3 module) — no separate server needed.

Why is it used?

Files and lists work for small amounts of data, but databases let you store huge amounts of structured data efficiently, enforce rules (like uniqueness), and query it precisely using SQL instead of writing loops yourself.

Topic 09 · Structured Storage
Simple explanation
Relational vs Non-Relational Databases

Relational (SQL)

  • Data stored in tables (rows & columns) with defined relationships.
  • Examples: MySQL, PostgreSQL, SQLite, SQL Server.
  • Uses Schema — a fixed structure defining columns and types.

Non-Relational (NoSQL)

  • Data stored flexibly — documents, key-value pairs, graphs.
  • Examples: MongoDB, Redis, Firebase.
  • No fixed schema — each record can have different fields.
Primary Key vs Foreign Key

Primary Key

  • A column that uniquely identifies each row in its own table.
  • Cannot be NULL, cannot repeat (e.g. student_id).

Foreign Key

  • A column in one table that refers to a Primary Key in another table.
  • Used to link related tables together (e.g. a course_id in an Enrollments table pointing to the Courses table).

Schema is the blueprint of a database — it defines table names, column names, data types, and constraints (like primary/foreign keys) before any actual data is added.

sqlite3 vs PRAGMA
import sqlite3 conn = sqlite3.connect("school.db") cur = conn.cursor() cur.execute("CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT, marks INTEGER)") conn.commit()

The sqlite3 module lets Python connect to, create, and query an SQLite database file. PRAGMA is a special SQLite command used to inspect or configure the database itself — e.g. PRAGMA table_info(students); lists all columns and their types in a table.

SELECT, WHERE, Operators, DISTINCT, ORDER BY, HAVING
SELECT name, marks FROM students WHERE marks > 60 ORDER BY marks DESC;
name marks B 85 A 70

SELECT chooses columns to display. WHERE filters individual rows before grouping, using operators like =, >, <, !=, AND, OR, LIKE, BETWEEN. ORDER BY col DESC/ASC sorts results.

SELECT DISTINCT department FROM employees;
department CS ME EEE

DISTINCT removes duplicate values from the result, showing each unique value only once.

SELECT department, COUNT(*) FROM employees GROUP BY department HAVING COUNT(*) > 2;
department COUNT(*) CS 4

WHERE filters rows before grouping; HAVING filters groups after a GROUP BY aggregation. You cannot use an aggregate function like COUNT() inside a WHERE clause — that's exactly what HAVING is for.

  • Simple, compact, good for comparing many groups.

What is it? Why is it used?
What is it?

Correlation measures the strength and direction of the linear relationship between two numeric variables, expressed as a number between -1 and +1. A heatmap visualises many correlations at once using colour intensity.

Why is it used?

Correlation helps identify which features are related to each other (useful before modelling), but it's one of the most misused statistics — exams frequently test whether you understand its limits.

Topic 14 · Relationships in Data
Simple explanation
Reading correlation values
+1 → perfect positive0 → no linear relationship-1 → perfect negative

Positive correlation

  • As one variable increases, the other also increases.
  • Example: total bill amount and tip amount in the Tips dataset.

Negative correlation

  • As one variable increases, the other decreases.
  • Example: hours of TV watched and exam score (in some studies).

Weak vs strong: values close to 0 (e.g. ±0.1) show a weak relationship; values close to ±1 (e.g. ±0.8) show a strong relationship. There's no single hard cutoff, but roughly: 0–0.3 weak, 0.3–0.7 moderate, 0.7–1.0 strong (in either direction).

Heatmap interpretation
import seaborn as sns sns.heatmap(tips_df.corr(numeric_only=True), annot=True, cmap='coolwarm')

A correlation heatmap is a grid where each cell shows the correlation between two variables, coloured by strength/direction (often dark red for strong positive, dark blue for strong negative, pale for near-zero). The diagonal is always 1.0 (a variable is perfectly correlated with itself).

Correlation vs Causation

The classic exam trap

  • Correlation means two variables move together — it does NOT prove that one causes the other.
  • Classic example: ice cream sales and drowning incidents are correlated (both rise in summer) — heat is the real hidden cause of both, not each other.
  • To claim causation, you generally need controlled experiments, not just an observed correlation.

What is it? Why is it used?
What is it?

An API (Application Programming Interface) is a defined way for one piece of software to request data or actions from another. In web APIs, your Python code (the client) sends a request over the internet to a server, which sends back a response.

Client and Server

Client

  • The one making the request — your Python script, browser, or app.

Server

  • The one holding the data/service, listening for requests and sending back responses.

GET

  • Requests/reads data from the server.

Bad: hardcoding the key

Real consequences

  • Bots constantly scan public GitHub repos for leaked keys — exposure can happen within minutes.
  • The key owner may see unexpected charges/usage, or the account may be suspended for abuse.
  • Fix: immediately revoke/regenerate the key, remove it from the code, and add it to .gitignore so it's never tracked by Git again.
Safe practices summary
  • Store secrets in a .env file, never directly in code.
  • Add .env to .gitignore so Git never tracks/uploads it.
  • Use different keys for development and production where possible.

VS
Standardization vs Min-Max Scaling
Standardization: (x-mean)/std → mean 0, std 1. Min-Max: (x-min)/(max-min) → squeezed into [0,1].
VS
Series vs DataFrame
Series = one labelled column. DataFrame = a full table of multiple Series sharing the same index.

loc vs iloc

WHERE vs HAVING

Primary Key vs Foreign Key
Primary Key uniquely identifies a row in ITS OWN table. Foreign Key refers to a Primary Key in ANOTHER table, linking them.

INNER JOIN vs LEFT JOIN
INNER JOIN keeps only matching rows from both tables. LEFT JOIN keeps ALL rows from the left table, with NULLs where there's no match.
VS
Histogram vs Bar Chart
Histogram shows the distribution of ONE continuous numeric variable (bars touch). Bar chart compares separate CATEGORIES (bars have gaps).

Correlation vs Causation
